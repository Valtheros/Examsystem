# แนวทาง UI/UX — งานเรียงจากบนลงล่าง

ใช้กับทุกบทบาทและทุกหน้าที่เพิ่มหรือแก้ไข ตั้งแต่ 13 กันยายน 2569 ตามข้อเสนอแนะผู้ใช้ หน้าที่กดได้ครบไม่ถือว่าใช้งานง่าย ถ้าผู้ใช้ยังต้องหาเองว่าควรกดอะไรต่อ

## หลักที่เลือกใช้

1. หน้าทำงานเป็นคอลัมน์เดียว: ชื่อรายการ/สถานะ → งานปัจจุบันและข้อมูลที่จำเป็น → ปุ่มขั้นตอนถัดไป → ข้อมูลประกอบ/ประวัติ ห้ามวางการทำงานซ้ายและขวาแข่งกัน
2. ปุ่มหลักหนึ่งปุ่มต่อขั้นที่กำลังทำ การทำงานย่อย เช่น เปิด PDF ใช้ลิงก์ชื่อเอกสารที่สื่อความหมาย งานจบเมื่อพิมพ์เสร็จ ไม่แสดงขั้นรับมอบ/แจกจ่าย
3. พับงานที่เสร็จแล้ว ประวัติ และตัวเลือกพิเศษไว้ ไม่ลบข้อมูลเดิม ไม่ซ่อน validation ที่ต้องใช้แก้ปัญหา
4. ทั้งแถวของรายการคำขอเป็นลิงก์จริง ไม่ต้องเล็งปุ่ม เปิด มี hover/focus และเปิดได้ด้วย Tab/Enter, Ctrl-click และเปิดแท็บใหม่ตามพฤติกรรมลิงก์
5. ปุ่มเป็นการเปลี่ยนข้อมูล ลิงก์เป็นการนำทาง/เปิดเอกสาร ห้ามสร้าง div onClick เพื่อเลียนแบบลิงก์หรือซ้อนปุ่มภายในลิงก์ทั้งแถว
6. ใช้ข้อความภาษาของผู้ใช้งาน ห้ามแสดงชื่อ table หรือคำอธิบาย implementation เช่น ExamRoom / hard-code ในคำแนะนำทั่วไป
7. จำนวนที่เกี่ยวข้องกันอาจวางเปรียบเทียบในแถวเดียวได้ แต่ขั้นตอนทำงานและปุ่มยืนยันต้องอ่านจากบนลงล่างทั้ง desktop และมือถือ
8. ใช้ shadcn/ui และ Sonner เดิม พื้นหลังเรียบ ความกว้างอ่านง่าย ไม่เพิ่มสี/การ์ด/สถิติที่แย่งความสำคัญจากงาน

## หน้าคำขอของหน่วยโสต

- รอตรวจ: แบบฟอร์ม → ไฟล์ต้นฉบับ → จำนวนห้อง → รับงาน; ส่งกลับเป็นส่วนที่เปิดเมื่อต้องใช้
- เตรียมพิมพ์: ยืนยันไฟล์/จำนวน → สร้างใบปะหน้าทุกห้อง → เริ่มพิมพ์ แสดงปุ่มหลักตามความพร้อมจริง แก้ไขแผนเป็นทางเลือกรองและซ่อนเริ่มงานขณะแก้ไข
- กำลังพิมพ์: ห้องแรก เปิดข้อสอบ/ใบปะหน้า/จัดซอง → ห้องถัดไป → ยืนยันพิมพ์เสร็จ
- พิมพ์เสร็จ: แสดง จบงานในระบบ พร้อมสรุปห้อง/ซอง/ยอดพิมพ์ ไม่แสดงปุ่มขั้นต่อไปหรือ QR ส่วนเอกสารย้อนหลังยังเปิดได้ตามสิทธิ์
- รอบสอบ: dropdown กลางภาค/ปลายภาค/รอบสอบอื่น ช่องชื่อกำหนดเองแสดงเฉพาะเมื่อเลือกอื่น

ฐานข้อมูล สถานะ สิทธิ์ การเก็บไฟล์ และ revision ของใบปะหน้ายังใช้กติกาเดิม ไม่มี migration หรือ reset ข้อมูลสำหรับการปรับ UX รอบนี้

## พื้นฐานภาษาภาพ 3 ตุลาคม 2569

- ใช้ PSU navy กับพื้นสีขาว/เทาอ่อนและฟอนต์ Noto Sans Thai เดิม ไม่มี gradient, glass, เงาก้อนใหญ่ หรือการ์ดสถิติเรียงเต็มจอ
- `Card` ในระบบงานเป็น section แบบเรียบ แบ่งด้วยหัวข้อ ระยะห่าง และเส้นบน ไม่ใช่กรอบโค้งที่ซ้อนกัน ฟอร์มและรายการห้องไม่เพิ่มกล่องครอบอีกชั้น
- หน้าหลักแสดงงานของบทบาทเป็นลิงก์แถวเต็ม สถิติเป็นข้อความรอง ไม่ใช้การ์ดตัวเลขและ CTA ซ้ำ
- ใช้โลโก้ PSU ฉบับตัดพื้นหลัง `/psu-logo-transparent.png` บนเว็บ เก็บ `/images.png` ต้นฉบับสำหรับ PDF คงเมนูและ URL เดิม โหมดสว่างเป็นค่าเริ่มต้น สลับมืดจากปุ่มบน header และจำค่าบนอุปกรณ์
- ปุ่ม/input/select เป้าหมายสัมผัสหลักอย่างน้อย 44px มี focus, skip link และเคารพ reduced motion; ตารางยาว scroll ภายใน ไม่ดันหน้าให้ล้นมือถือ
- ฟอร์มอาจารย์เมื่อเปลี่ยนขั้นตอนให้เลื่อนและย้าย focus กลับจุดเริ่มขั้นนั้น ไม่ค้างบริเวณท้ายฟอร์ม
- เพิ่ม loading skeleton, หน้าข้อผิดพลาดพร้อม retry และ empty state ของรายการจัดการ โดยไม่แสดงข้อความ error ภายในฐานข้อมูลให้ผู้ใช้
- ไม่เปลี่ยน schema, สิทธิ์, ขั้นงาน, จำนวนพิมพ์, รูปแบบ PDF หรือข้อมูลเดิมในรอบ redesign

## ปรับภาษาภาพ 4 ตุลาคม 2569

ผู้ใช้เห็นว่าหน้าเว็บเรียบเกินไป จึงปรับน้ำหนักสี ลำดับสายตา และรายละเอียดการโต้ตอบ โดยคงหลักงานจากบนลงล่างไว้ ใช้ `design-taste-frontend` เฉพาะหลักที่เหมาะกับระบบทำงานจริง เพราะ skill เน้นหน้าแนะนำผลิตภัณฑ์ ไม่ใช่ dashboard หรือแบบฟอร์มซับซ้อน ระบบยังใช้ shadcn/ui และ Noto Sans Thai เดิม

กำหนด `DESIGN_VARIANCE = 4` ให้มีเอกลักษณ์แต่คาดเดาตำแหน่งงานได้, `MOTION_INTENSITY = 3` ใช้การเคลื่อนไหวสั้นเฉพาะ feedback และ `VISUAL_DENSITY = 5` ให้มีข้อมูลพอทำงานโดยไม่อัดแน่น

| จุดที่พบก่อนปรับ | การปรับและเหตุผล |
| --- | --- |
| เมนูและเนื้อหามีพื้นสว่างใกล้กัน ทำให้พื้นที่นำทางไม่ชัด | ใช้ sidebar สี PSU navy กับพื้นที่งานสว่าง มี selected state, breadcrumb และข้อมูลบัญชีที่อ่านง่าย |
| หัวข้อ งานหลัก และข้อมูลรองมีน้ำหนักใกล้กัน | แยกหัวทักทายด้วยสีอ่อน เพิ่มไอคอนที่สัมพันธ์กับงานจริง และเน้นงานแรก โดยทุกแถวยังเป็นลิงก์ที่กดได้ทั้งแถว |
| หน้าเข้าสู่ระบบมีพื้นที่ว่างมากและขาดบริบท | จัดส่วนแนะนำขั้นตอนข้างฟอร์มบน desktop และย่อส่วนแนะนำบนมือถือเพื่อให้เข้าถึงช่องเข้าสู่ระบบได้เร็ว |

- ใช้พื้นที่งานหลักแบบกระดาษหนึ่งชั้นบนพื้นเทาอมฟ้า ไม่เปลี่ยนรายการและสถิติเป็นกริดการ์ดจำนวนมาก ส่วนภายในยังแบ่งด้วยหัวข้อและระยะห่าง
- Sidebar กว้าง 264px บน desktop; header สูง 64px บนมือถือใช้เมนูแบบ Sheet และปุ่มไอคอนที่มีชื่อสำหรับโปรแกรมอ่านหน้าจอ
- โลโก้เดิมอยู่บนพื้นสว่างเล็ก ๆ เมื่อวางใน sidebar ไม่แก้ตัวโลโก้ และไม่เพิ่มข้อความคณะใต้ชื่อระบบ
- สีพื้น ข้อความ ขอบ และ selected state ใช้ semantic tokens รองรับทั้งโหมดสว่างและมืด คงโหมดสว่างเป็นค่าเริ่มต้น
- ปุ่มและช่องควบคุมหลักคงเป้าหมายสัมผัสอย่างน้อย 44px มี keyboard focus, skip link และ hover ที่สื่อว่ากดได้; การเคลื่อนลูกศรใช้ `motion-safe` และเคารพ reduced motion
- หน้าคำขอ ฟอร์ม และตารางยังทำงานตามลำดับเดิม ไม่เปลี่ยน URL เมนู สิทธิ์ สถานะ ยอดพิมพ์ หรือข้อมูลในฐานข้อมูล

การตรวจรับด้านภาพรอบนี้ต้องครอบคลุม desktop/mobile ทั้งสองโหมดสี การเปิดเมนู การใช้คีย์บอร์ด และการกลับมาใช้ฟอร์มเดิม หมวดนี้เป็นแนวทางออกแบบ ไม่ใช่รายงานผลการทดสอบ

### ผลตรวจการปรับหน้าตา 4 ตุลาคม 2569

- `npm run lint` ผ่าน; Vitest ผ่าน 50 tests และข้าม database integration 3 tests ที่ไม่ได้เปิดใช้ในรอบนี้
- `npm run build` และ production build ใน Docker ผ่าน; web กลับมา healthy โดย bootstrap ข้ามการสร้างผู้ดูแลเมื่อพบบัญชีเดิม
- Playwright ชุดเดิม `usability`, `smoke`, `feedback` ผ่าน 14 tests บน Chromium และ mobile โดยใช้ฐานข้อมูล/bucket ทดสอบแยก ตรวจเมนูและหน้าหลักทั้ง 4 บทบาท; การทดสอบ Factory Reset ใช้ mock ไม่ล้างข้อมูลจริง
- ตรวจภาพหน้าเข้าสู่ระบบ หน้าหลัก และหน้าเตรียมพิมพ์ที่ขนาด 360, 768, 1024, 1440px รวมโหมดสว่าง/มืดตามหน้าที่เกี่ยวข้อง ไม่พบหน้าเอกสารล้นแนวนอน ยังเรียงงานพิมพ์จากบนลงล่าง
- Lighthouse หน้าเข้าสู่ระบบจาก Docker บน localhost: desktop ได้ Performance 100 / Accessibility 100; mobile ได้ Performance 89 / Accessibility 100, LCP 3.5 วินาที, CLS 0 และตรวจ contrast ผ่าน เป็นผล lab ครั้งเดียวภายใต้การจำลอง mobile throttling ไม่ใช่การรับประกันประสิทธิภาพเซิร์ฟเวอร์จริง
- ภาพและรายงานรอบตรวจอยู่ใน `output/playwright/` ซึ่งเป็นผลลัพธ์ทดสอบเฉพาะเครื่อง ไม่ commit ข้อมูลทดสอบหรือ credentials
- รอบนี้ไม่ได้ทดสอบ workflow อัปโหลดจนจบพิมพ์ซ้ำทั้งหมด และไม่ได้เปลี่ยน business logic, schema หรือข้อมูลจริง

## การตรวจรับต่อเนื่อง

### ปุ่มงานสำคัญ 6 ตุลาคม 2569

- คง shadcn/ui, PSU navy, Noto Sans Thai และลำดับงานเดิม (DESIGN_VARIANCE 4, MOTION_INTENSITY 2, VISUAL_DENSITY 5) ปรับเฉพาะความชัดเจน ไม่เพิ่ม animation หรือการ์ดซ้อน
- ส่งกลับแก้ไขแสดงเหตุผลและปุ่มบนหน้าตรวจคำขอทันที ยกเลิกคำขอแสดงปุ่มก่อนข้อมูลย้อนหลังและยังยืนยันด้วย AlertDialog ปุ่มอันตรายใช้พื้นสีแดงกับข้อความตัดกันทั้งสองโหมด ไม่ใช้แดงอ่อนกับตัวหนังสือเล็ก
- แก้ไขไฟล์/จำนวนใช้ปุ่มมีขอบและไอคอน เป้าหมายสัมผัส 44px ไม่ใช้ ghost กลืนกับพื้นหลัง รายการขั้นตอนทั้งหมดของระบบถูกนำออกจากภาพรวม แต่ขั้นตอนเตรียมพิมพ์ยังอยู่ในหน้างาน
- จัดการบัญชีแสดง “ตั้งรหัสผ่านชั่วคราว” เฉพาะบัญชีที่ยังต้องตั้งรหัสส่วนตัว บัญชีที่ตั้งแล้วใช้ “แก้รหัสผ่าน” ไม่อ่าน/แสดงรหัสเดิม แจ้งก่อนบันทึกว่าจะยกเลิก session และให้ผู้ใช้ตั้งรหัสส่วนตัวใหม่

### ล้างข้อมูลสำหรับผู้ดูแลระบบ 5 ตุลาคม 2569

- คงหน้า `/dashboard/reset` และเมนู Factory Reset เดิม เพิ่มทางเข้าจากภาพรวม “ล้างข้อมูลงานสอบ” หน้าจัดการข้อมูลเรียงบนลงล่าง โดยตัวเลือกเก็บผู้ใช้เป็นส่วนหลัก ส่วน Factory Reset ที่ลบผู้ใช้อยู่แยกด้านล่าง ไม่ใช้ dropdown เปลี่ยนขอบเขตในกล่องยืนยันเดียวกัน
- ก่อนกดแสดงชัดว่าลบงานสอบและไฟล์ทุกเวอร์ชัน แต่เก็บทุกบัญชี รหัสผ่าน บทบาท session และ Audit Log เปิดช่องยืนยันเฉพาะเมื่อกด ไม่วางช่องรหัสผ่านสองชุดบนหน้าปกติ
- ใช้ AlertDialog โฟกัสปุ่มยกเลิกก่อน ใช้ได้ทั้งเมาส์/คีย์บอร์ด/มือถือ ปุ่มยืนยันปิดจนกรอกรหัสผ่านและข้อความตรง ใช้ `CLEAR EXAM DATA` คนละข้อความกับ `RESET EXAM SYSTEM` ตรวจซ้ำฝั่ง server และป้องกันกดซ้ำ
- ผิดพลาดคง dialog และข้อมูลที่กรอกไว้ แสดงข้อความไทยใกล้ฟอร์มพร้อม toast; สำเร็จหรือไฟล์ตกค้างแสดงผลบนหน้า ล้างรหัสผ่านจาก state และ refresh ข้อมูล Retry ไฟล์ต้องยืนยันใหม่และไม่ล้างฐานข้อมูลซ้ำ
- ประยุกต์ design-taste-frontend แบบ preserve สำหรับระยะห่าง ลำดับสายตา และ accessibility บน shadcn/ui เดิม: DESIGN_VARIANCE 4, MOTION_INTENSITY 2, VISUAL_DENSITY 5 ไม่ใช้ layout หน้าโฆษณา animation ตกแต่ง หรือการ์ดซ้อนในส่วนจัดการระบบ

### หน้าจัดเตรียมสอบ 5 ตุลาคม 2569

- รอบสอบ ห้อง รายวิชา และตารางสอบใช้ลำดับหัวข้อ → ฟอร์มที่กำลังเพิ่ม/แก้ไข (เมื่อเปิด) → รายการ แสดงรายการทันทีเมื่อเปิดหน้าปกติ ไม่ให้ฟอร์มว่างหลายชุดผลักรายการลงท้ายหน้า
- ใช้ปุ่มเพิ่มที่มีชื่อชัดเจน ฟอร์มเปิดด้วยลิงก์จริงและปิดกลับรายการได้ รักษา URL/เมนูเดิม เลือกแก้ไขจากแถวแล้วเติมข้อมูลเดิมให้ครบ
- ปุ่มแก้ไข/ลบขนาดสัมผัส 44px อยู่แถวเดียวชิดขวา ไม่ใช้ลิงก์ขีดเส้นใต้หรือย่อหน้าข้อความล็อกในเซลล์จัดการ รายการล็อกกดดูเหตุผลได้ใน AlertDialog โดยไม่เสนอให้ลบ
- หัวตารางพื้นสีรองอ่อน แยกข้อมูลหลัก/ข้อมูลรองด้วยน้ำหนักตัวอักษร ไม่ใช้สีกล่องสถิติหรือกรอบการ์ดซ้อน ตารางเลื่อนเฉพาะภายในบนมือถือ
- รอบสอบที่มีประวัติคำขอแล้วแก้ไข/ลบไม่ได้ การลบรอบที่ยังไม่ถูกใช้ต้องแจ้งว่าลบรายวิชาและตารางในรอบด้วย ไม่ลบคำขอ ไฟล์ หรือประวัติเดิม

- ส่วนชื่อระบบข้างโลโก้ไม่แสดงบรรทัดคณะวิทยาศาสตร์ทุกหน้า รวม sidebar/เมนูมือถือ ตามคำสั่งล่าสุด ไม่เปลี่ยนหัวข้อคณะใน PDF ใบปะหน้าซอง

- คลิกแถวและใช้คีย์บอร์ดเปิดคำขอได้
- หน้างานเสร็จไม่มีปุ่มส่งมอบ ไม่มีลิงก์สแกน และไม่มีเมนูรับมอบ/แจกจ่ายทั้งหน่วยโสตและเจ้าหน้าที่
- ประวัติอยู่ต่ำกว่างานหลักทุก viewport 360/768/1024/1440 ไม่ล้นจอ และเปิดดูข้อมูลเดิมได้
- ยืนยันแผน/สร้าง PDF/เริ่มพิมพ์ยังตรวจเงื่อนไขฝั่ง server ไม่ใช่ซ่อนปุ่มอย่างเดียว
- ทดสอบกระบวนการ 4 บทบาทด้วยฐานข้อมูลและ bucket ทดสอบแยกจากจริง
