# ข้อกำหนดความต้องการของระบบจัดพิมพ์ข้อสอบ คณะวิทยาศาสตร์

## 1. วัตถุประสงค์และขอบเขต

ระบบใช้บริหารกระบวนการจัดพิมพ์ข้อสอบของคณะวิทยาศาสตร์ ตั้งแต่การเตรียมรอบสอบ การส่งต้นฉบับข้อสอบ การตรวจสอบและตัดข้อสอบ การพิมพ์ การส่งมอบ ไปจนถึงการแจกจ่ายข้อสอบเข้าห้องสอบ โดยในแต่ละภาคการศึกษามีการสอบ 2 ครั้ง เช่น สอบกลางภาคและสอบปลายภาค

## 2. บทบาทผู้ใช้

ระบบมีผู้ใช้ 4 บทบาทเท่านั้น

1. **ผู้ดูแลระบบ** — สร้างและจัดการบัญชีผู้ใช้ทั้งหมด
2. **เจ้าหน้าที่** — จัดเตรียมรอบสอบ รายวิชา และดำเนินการส่งมอบ/แจกจ่ายข้อสอบ
3. **อาจารย์** — จัดทำ ส่ง แก้ไข และติดตามต้นฉบับข้อสอบของรายวิชาที่รับผิดชอบ
4. **หน่วยโสต** — ตรวจสอบ ตัด เรียกดู และพิมพ์ข้อสอบ รวมถึงบันทึกการส่งมอบ

> การเปลี่ยนชื่อบทบาทจากเอกสารเดิม: `Admin` → `ผู้ดูแลระบบ`, `เจ้าหน้าที่ดำเนินการสอบ` → `เจ้าหน้าที่`, `เจ้าหน้าที่จัดพิมพ์ข้อสอบ` → `หน่วยโสต`, และ `อาจารย์` คงเดิม

## 3. สถานะหลักของคำขอจัดพิมพ์

`ฉบับร่าง` → `รอตรวจสอบ` → `ตัดข้อสอบ` → `กำลังพิมพ์` → `พิมพ์เสร็จแล้ว` → `ส่งมอบแล้ว`

เส้นทางกรณีแก้ไข: `รอตรวจสอบ` → `ปฏิเสธ/ส่งกลับแก้ไข` → อาจารย์แก้ไขและส่งใหม่

## 5. กฎทางธุรกิจสำคัญ

- บัญชีของผู้ใช้ทุกบทบาทนอกเหนือจากผู้ดูแลระบบเริ่มต้น ต้องถูกสร้างโดยผู้ดูแลระบบ ไม่มีการสมัครสมาชิกด้วยตนเอง
- อาจารย์เห็นและดำเนินการได้เฉพาะรายวิชา/คำขอของตนเอง
- การแก้ไขหรือลบข้อสอบของอาจารย์ทำได้จนกว่าคำขอจะเข้าสู่สถานะ `ตัดข้อสอบ`
- หน่วยโสตเป็นผู้เดียวที่รับคำขอเข้าสถานะ `ตัดข้อสอบ` และดำเนินการเกี่ยวกับไฟล์สำหรับพิมพ์
- การพิมพ์ต่อห้องต้องมีข้อสอบสำรอง 1 ชุดเสมอ
- ทุกการเปลี่ยนสถานะต้องเก็บผู้ดำเนินการ วันเวลา และหมายเหตุ/เหตุผล (ถ้ามี) เพื่อให้ตรวจสอบย้อนหลังได้

| NFR-0001 | Performance / Capacity | ระบบต้องรองรับไฟล์ข้อสอบ PDF ขนาดสูงสุด 100 MB | การอัปโหลดตรงไป Private MinIO บนเครื่องเซิร์ฟเวอร์ผ่านเครือข่ายอย่างน้อย 20 Mbps ต้องเสร็จภายใน 120 วินาที | M | ทดสอบอัปโหลดไฟล์ 100 MB |
| NFR-0003 | Availability | ระบบควรเปิดให้อาจารย์ส่งข้อสอบได้ตลอดเวลา | ให้บริการแบบ Best Effort ตามข้อจำกัด Supabase Free และเครื่องเซิร์ฟเวอร์ โดยไม่รับรอง SLA 99.5% และต้องหลีกเลี่ยงการปิดปรับปรุงช่วงสอบ | M | ตรวจรายงาน uptime และสถานะบริการรายเดือน |
| NFR-0004 | Data Recovery | ระบบรุ่นนี้ไม่มี Automatic Backup | หน้าจอ Factory Reset ต้องแจ้งชัดเจนว่ากู้คืนไม่ได้ ต้องยืนยันรหัสผ่านและข้อความ `RESET EXAM SYSTEM` ก่อนดำเนินการ | M | ทดสอบเงื่อนไขยืนยัน Factory Reset |
| NFR-0005 | Usability / UI/UX | ระบบต้องรองรับคอมพิวเตอร์ แท็บเล็ต และสมาร์ทโฟน | หน้าหลักใช้งานได้ที่ความกว้าง 360–1440 พิกเซล และเจ้าหน้าที่อัปเดตสถานะหรือสแกน QR Code บนมือถือได้ | M | ทดสอบบนหน้าจอ 4 ขนาด |
| NFR-0006 | Usability / UI/UX | แบบฟอร์มส่งข้อสอบต้องใช้งานง่าย | อาจารย์สร้างและส่งคำขอได้ไม่เกิน 5 ขั้นตอนหลัก | M | นับขั้นตอนจาก dashboard จนส่งสำเร็จ |
| NFR-0007 | Security & Compliance | ไฟล์ข้อสอบต้องถูกเข้ารหัส | ใช้ HTTPS/TLS 1.2 ขึ้นไปขณะส่งข้อมูล และวาง Docker volume ของ MinIO บนดิสก์ที่เข้ารหัส AES-256 หรือเทียบเท่า | M | ตรวจ TLS และการเข้ารหัสดิสก์ของเครื่องเซิร์ฟเวอร์ |
| NFR-0008 | Security & Compliance | ระบบต้องควบคุมสิทธิ์และป้องกันการเข้าถึงไฟล์โดยไม่ได้รับอนุญาต | ไม่มี self-registration ตรวจ session/บทบาท/เจ้าของ/สถานะที่ฝั่งเซิร์ฟเวอร์ ใช้รหัสผ่านอย่างน้อย 12 ตัวอักษร และใช้ Presigned URL อายุสั้น โดยระบบรุ่นนี้ไม่ใช้ 2FA | M | ทดสอบสิทธิ์แต่ละบทบาท IDOR บัญชีปิดใช้งาน และ URL หมดอายุ |
| NFR-0009 | Security & Compliance | ระบบต้องเก็บ Audit Log ของเหตุการณ์สำคัญ | บันทึกผู้ดำเนินการ วันเวลา และรายการเข้าสู่ระบบ อัปโหลด ดาวน์โหลด พิมพ์ และเปลี่ยนสถานะ โดยเก็บอย่างน้อย 1 ปี | M | ตรวจ log จากเหตุการณ์ทดสอบ |
| NFR-0010 | Compatibility | ระบบต้องรองรับเว็บเบราว์เซอร์ยอดนิยม | งานหลักต้องใช้งานได้บน Google Chrome, Microsoft Edge, Mozilla Firefox และ Safari เวอร์ชันปัจจุบัน | M | Cross-browser test ก่อน release |
