# ข้อกำหนดความต้องการของระบบจัดพิมพ์ข้อสอบ คณะวิทยาศาสตร์

## 1. วัตถุประสงค์และขอบเขต

ระบบใช้บริหารกระบวนการจัดพิมพ์ข้อสอบของคณะวิทยาศาสตร์ ตั้งแต่เตรียมรอบสอบ ส่งต้นฉบับ ตรวจสอบและเตรียมพิมพ์ จนพิมพ์ข้อสอบพร้อมใบปะหน้าซองเสร็จ รอบมาตรฐานคือกลางภาคและปลายภาค และรองรับรอบอื่นที่กรอกชื่อเอง การนำซองไปส่งเจ้าหน้าที่และห้องสอบทำภายนอกระบบ

## 2. บทบาทผู้ใช้

ระบบมีผู้ใช้ 4 บทบาทเท่านั้น

1. **ผู้ดูแลระบบ** — สร้างและจัดการบัญชีผู้ใช้ทั้งหมด
2. **เจ้าหน้าที่** — จัดเตรียมรอบสอบ รายวิชา ห้อง และตารางสอบ ติดตามการจัดพิมพ์
3. **อาจารย์** — จัดทำ ส่ง แก้ไข และติดตามต้นฉบับข้อสอบของรายวิชาที่รับผิดชอบ
4. **หน่วยโสต** — ตรวจสอบ เตรียมพิมพ์ พิมพ์ข้อสอบพร้อมใบปะหน้าซอง และยืนยันพิมพ์เสร็จ

> การเปลี่ยนชื่อบทบาทจากเอกสารเดิม: `Admin` → `ผู้ดูแลระบบ`, `เจ้าหน้าที่ดำเนินการสอบ` → `เจ้าหน้าที่`, `เจ้าหน้าที่จัดพิมพ์ข้อสอบ` → `หน่วยโสต`, และ `อาจารย์` คงเดิม

## 3. สถานะหลักของคำขอจัดพิมพ์

`ฉบับร่าง` → `รอตรวจสอบ` → `ตัดข้อสอบ` → `กำลังพิมพ์` → `พิมพ์เสร็จแล้ว` (สิ้นสุดงาน)

เส้นทางกรณีแก้ไข: `รอตรวจสอบ` → `ปฏิเสธ/ส่งกลับแก้ไข` → อาจารย์แก้ไขและส่งใหม่

## 5. กฎทางธุรกิจสำคัญ

- บัญชีของผู้ใช้ทุกบทบาทนอกเหนือจากผู้ดูแลระบบเริ่มต้น ต้องถูกสร้างโดยผู้ดูแลระบบ ไม่มีการสมัครสมาชิกด้วยตนเอง
- อาจารย์เห็นและดำเนินการได้เฉพาะรายวิชา/คำขอของตนเอง
- การแก้ไขหรือลบข้อสอบของอาจารย์ทำได้จนกว่าคำขอจะเข้าสู่สถานะ `ตัดข้อสอบ`
- หน่วยโสตเป็นผู้เดียวที่รับคำขอเข้าสถานะ `ตัดข้อสอบ` และดำเนินการเกี่ยวกับไฟล์สำหรับพิมพ์
- การพิมพ์ต่อห้องมีสำรองเริ่มต้น 1 ชุด หน่วยโสตแก้เป็นจำนวนเต็มตั้งแต่ 0 ได้
- ทุกการเปลี่ยนสถานะต้องเก็บผู้ดำเนินการ วันเวลา และหมายเหตุ/เหตุผล (ถ้ามี) เพื่อให้ตรวจสอบย้อนหลังได้

# การเข้าใช้งานแทนผู้ใช้ (เพิ่มเติม)

- ผู้ดูแลระบบกด “เข้าใช้งานแทน” จากหน้าจัดการผู้ใช้ได้ โดยไม่ต้องใช้รหัสผ่านของบัญชีเป้าหมาย
- ใช้ Better Auth Admin plugin กับบัญชีเจ้าหน้าที่ อาจารย์ และหน่วยโสตที่เปิดใช้งานและเปลี่ยนรหัสผ่านชั่วคราวแล้วเท่านั้น ตรวจเงื่อนไขฝั่ง server แม้เรียก API โดยตรง
- แสดงแถบเตือนชัดเจนว่าการดำเนินการมีผลจริง พร้อมปุ่ม “กลับบัญชีผู้ดูแลระบบ” ทุกหน้า; ใช้สิทธิ์และเจ้าของข้อมูลของบัญชีเป้าหมาย ไม่คงสิทธิ์ผู้ดูแลในช่วงนี้
- Session เข้าใช้งานแทนอายุสูงสุด 1 ชั่วโมง ไม่เปิดให้สวมสิทธิ์ผู้ดูแลระบบอื่น
- เก็บ `IMPERSONATION_STARTED` และ `IMPERSONATION_ENDED` เมื่อ session ถูกสร้าง/ลบ พร้อมรหัส session บัญชีผู้ดูแลและบัญชีเป้าหมาย; การหมดอายุโดยไม่มีการลบ session ไม่ใช่เหตุการณ์จบแบบกดกลับ

## Workflow ฉบับปรับปรุง 13 กันยายน 2569

- เจ้าหน้าที่เลือกวิชา อาจารย์ วัน เวลา และหลายห้องได้ ห้องจริงเก็บความจุเท่านั้น ตรวจเวลาทับซ้อนใน transaction ภายใต้ lock ของห้อง รวมถึงบันทึกพร้อมกัน
- มีคำขอที่ยังไม่ยกเลิกแล้ว ห้ามแก้วิชา/ตารางย้อนหลัง การสร้างคำขอกับการแก้ตารางใช้ lock ของวิชาเดียวกัน
- อาจารย์ส่งออนไลน์ 3 ขั้นตอน: เลือกวิชา → กรอกแบบฟอร์ม/จำนวนรายห้อง/แนบ PDF → ตรวจทานและส่ง; บันทึกร่างและลองอัปโหลดใหม่ได้โดยไม่สร้างคำขอซ้ำ
- จำนวนอาจารย์คือจำนวนชุดที่ขอ (1 ชุด/คน) > 0 ไม่เกินความจุ ไม่มีค่าเริ่มต้นจากความจุห้อง หน่วยโสตปรับยอดหลักและสำรองแยกกัน ผลรวมบน server = หลัก + สำรอง; ยอดหลักเปลี่ยนต้องมีเหตุผลและ Audit Log
- แบบฟอร์ม JSONB มีสาขา ภาษา รูปแบบพิมพ์และรายละเอียดอื่น อุปกรณ์/ข้อกำหนด กระดาษคำตอบคอมพิวเตอร์ คำอธิบาย ประเภทใน/นอกตาราง เบอร์ติดต่อ; ข้อมูลวิชา/ภาค/เวลาแสดงจากตาราง ตัวเลือก ไม่มี ห้ามใช้ร่วมกับอุปกรณ์อื่น
- หน่วยโสตเปิด PDF ระหว่างรอตรวจสอบได้ เจ้าหน้าที่เปิดข้อสอบไม่ได้ รับงานแล้วเลือกต้นฉบับล่าสุดให้ ไม่บังคับอัปโหลดพร้อมพิมพ์
- หน่วยโสตยืนยันไฟล์และจำนวนก่อนสร้างใบปะหน้า เมื่อเปลี่ยนเพิ่ม revision ใบปะหน้าเก่าเริ่มพิมพ์ไม่ได้ ต้องสร้างรุ่นปัจจุบันครบทุกห้อง ล็อกแผนหลังเริ่มพิมพ์
- ใบปะหน้า A4 ตามแบบฟอร์มคณะวิทยาศาสตร์ มหาวิทยาลัยสงขลานครินทร์ ใช้โลโก้ public/images.png แสดงวิชา รหัส ตอน วัน เวลา ห้อง เลขซอง ยอดอาจารย์ หลัก สำรอง รวม และอุปกรณ์/คำแนะนำ ไม่มี QR ช่องห้องทำงาน เข้าสอบจริง/ขาดสอบ/รายชื่อ/ลายเซ็น/หมายเหตุเว้นว่างสำหรับเขียน รายละเอียดที่ยาวต่อหน้าภาคผนวกโดยไม่ตัดข้อมูล
- การพิมพ์ใช้หน้าต่าง PDF ของ browser ผู้ใช้ตั้งจำนวน/รูปแบบพิมพ์และยืนยันเอง ไม่ตรวจจับเครื่องพิมพ์
- เก็บไฟล์และใบปะหน้าทุกรุ่นเมื่อยกเลิก ไม่มีการลบอัตโนมัติ ตารางรับมอบ/แจกจ่ายและ token เก่าเก็บเพื่อประวัติเท่านั้น ไม่สร้างรายการใหม่ งานใหม่จบที่พิมพ์เสร็จแล้ว
- Migration 0004 เพิ่มข้อมูลในตารางเดิม รักษาสถานะ ยอดรวม และประวัติเดิม ไม่เดาไฟล์ที่เคยพิมพ์ งานเก่ายังไม่เริ่มต้องยืนยันแผนก่อน ส่วนแบบฟอร์มเดิมแสดง ไม่ได้ระบุในระบบเดิม และกรอกส่วนจำเป็นก่อนส่งใหม่
- ไม่เพิ่ม 2FA, อ่านอีเมล, automatic backup หรือเกณฑ์ 200 concurrent users
